# 분석 이력 웹 UI 디자인 계약

## 화면의 실제 역할

사용자가 과거 분석을 빠르게 찾고, 전문 애널리스트의 종합 의견을 읽은 뒤, 판단을 구성한 시나리오·원자 주장·출처까지 역추적하는 것이 제품 화면의 역할이다.

주 사용자는 프로젝트 소유자 한 명이다. 목록의 주 행동은 **종목 또는 run ID로 분석을 찾는 것**이고, 상세의 주 행동은 **종합 의견과 판단 변화 조건을 파악한 뒤 근거를 검토하는 것**이다. standalone 보고서와 원본 JSON은 보조 행동이다.

## 디자인 방향

- 한국 증권 리서치 문서처럼 제목 체계를 작고 분명하게 유지한다.
- 흰색 문서 면, 옅은 회색 배경, 짙은 남색을 사용해 장시간 읽기 쉽게 만든다.
- 큰 영문 장식 문구와 세리프 중심 편집물 분위기를 사용하지 않는다.
- 화면에 보이는 설명과 상태 문구는 한국어로 작성한다. 종목 코드·출처 식별자·파일 형식처럼 번역하면 의미가 흐려지는 기술 값만 원문을 유지한다.
- 넓은 장식 영역보다 실제 데이터와 근거 연결을 우선한다.

## 정보 계층

1. 현재 위치와 로컬·읽기 전용 상태
2. 검색 입력
3. 전체 실행 수·종목 수·최근 기준일·인덱싱 오류
4. 최근 분석 및 종목별 최신 분석
5. 보고서 열기

상세 화면에서는 다음 순서를 사용한다.

1. 종목·기준일·검토·주문 없음 상태
2. 애널리스트 한줄 결론·확신 수준·핵심 투자 논지
3. 기술·펀더멘털·뉴스·반대 관점의 종합과 판단을 바꿀 신호
4. 상승·기준·하락 시나리오의 조건과 무효화
5. 분석 영역별 원자 주장과 직접 연결된 출처
6. 전체 출처 레지스터
7. 충돌하는 증거와 분석 한계

비교 화면은 이전·비교 두 실행을 같은 폭으로 배치하고, 최상위 판단·시나리오·원자 주장 변화 순서로 읽게 한다. 시스템 화면은 데이터베이스, 60초 동기화와 인덱싱 오류를 한 화면에서 확인하게 한다.

## 허용하는 구성 요소

- 상단 전역 내비게이션: 홈, 분석 이력
- 실제 동작하는 검색·필터 양식
- 데이터 밀도가 높은 분석 목록과 표
- 검토 결과와 분석 주기를 나타내는 작은 텍스트 배지
- 키보드 초점이 분명한 링크·입력·선택·버튼
- 페이지네이션
- 목적이 구체적인 빈 상태와 오류 상태

## 반드시 구현할 상태

- 분석 데이터가 있는 정상 상태
- 분석 결과 파일이 하나도 없는 빈 상태
- 필터 결과가 없는 상태
- 별도 웹 보고서가 없는 상태
- 존재하지 않는 보고서의 404 상태
- 존재하지 않는 분석·종목 타임라인의 404 상태
- 주장이 없는 생략된 분석 영역 상태
- 외부 주소가 안전한 웹 주소가 아닐 때 링크를 제한하는 상태
- 서버 내부 오류의 안전한 오류 상태

서버에서 화면을 완성하므로 별도의 클라이언트 로딩 화면은 만들지 않는다. 로컬 단일 사용자 제품이므로 권한 상태도 최소 기능 범위에 없다.

## 반응형 규칙

- 데스크톱에서는 분석을 행 중심 목록으로 표현한다.
- 760px 이하에서는 각 행을 라벨이 있는 세로 기록으로 재배치한다.
- 검색 필터는 모바일에서 한 열로 바뀐다.
- 주요 링크와 입력 요소의 최소 높이는 42픽셀을 유지한다.
- 가로 스크롤에 의존해 데스크톱 표를 축소하지 않는다.
- 3열 시나리오는 1040px 이하에서 한 열의 연속 문서로 바뀐다.
- 주장과 출처 행은 760px 이하에서 라벨·본문·연결 링크 순으로 쌓는다.

## 거부하는 기본 패턴

- 의미 없는 카드 격자와 장식용 대시보드
- 가짜 실시간 가격, 수익률, 차트, 활동 목록
- 매수·매도 버튼 또는 투자 행동을 유도하는 색상 사용
- 장식용 그라데이션, 빛 번짐, 유리 효과, 큰 그림자
- 동작하지 않는 내비게이션과 자리표시자 입력 요소
- `개요`, `인사이트`, `더 알아보기`처럼 목적이 모호한 라벨
- 모바일에서 데스크톱 표만 축소하는 방식

## 시각 언어

화려한 매매 화면이나 편집 잡지가 아니라 한국어 리서치 노트를 지향한다. 옅은 회색 배경, 흰색 문서 면, 짙은 남색을 기본으로 사용하고 초록색은 검증, 붉은색은 오류와 무효화를 표시한다. 색상은 의미를 보조하며 모든 상태는 텍스트로도 표현한다.
