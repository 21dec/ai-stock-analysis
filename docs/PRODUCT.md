# 제품 정의: 개인 투자 의사결정 시스템

## 문제

지금까지의 분석 실험은 차트, 지표, 뉴스, 보고서 형식을 검증하는 데 유용했다. 하지만 분석 입력과 판단 과정이 실행마다 달라질 수 있고, 결론이 어떤 근거에서 나왔는지 또는 실제 결과가 어땠는지를 일관되게 비교하기 어렵다.

이 프로젝트는 분석의 양을 늘리는 대신 **재현성, 추적성, 반증 가능성, 사후 학습**을 제품의 중심에 둔다.

## 사용자와 핵심 작업

초기 사용자는 프로젝트 소유자 한 명이다. 핵심 작업은 다음과 같다.

> 관심 종목에 대해 현재 근거를 확인하고, 상승·기준·하락 조건을 비교한 뒤, 내 판단을 기록하고 나중에 그 판단의 품질을 평가한다.

## MVP 범위

### 포함

- 국내·미국 상장 주식의 종목별 분석 실행
- 기술·펀더멘털·뉴스의 독립 분석
- 출처·주장·신뢰도·충돌을 포함한 evidence artifact
- 상승·기준·하락 시나리오와 trigger/invalidation
- 독립 반대 검토와 결정적 검증
- 검증된 evidence에서 재현 가능한 HTML 보고서 생성
- 실행별 artifact 보관

### 다음 수직 기능

- 로컬 웹에서 분석 이력을 탐색하는 읽기 전용 대시보드
- 종목별 분석 타임라인과 두 실행 비교
- 이후 사용자의 판단과 매매 근거를 기록하는 투자 저널
- 시나리오별 결과와 무효화 도달 여부 추적
- 분석 방법별 적중률이 아닌 의사결정 품질 평가

### 제외

- 자동 주문 및 주문 추천
- 수익을 보장하거나 하나의 목표주가를 제시하는 기능
- 검증되지 않은 실시간 데이터의 자동 사용
- 초기 단계의 다중 사용자, 결제, 소셜 기능
- 근거 없는 단일 점수로 복잡한 분석을 축약하는 기능

## 성공 기준

MVP는 다음 조건을 만족하면 성공이다.

1. 동일한 evidence 입력으로 의미상 동일한 보고서가 생성된다.
2. 필수 출처, 시나리오 또는 반대 검토가 빠지면 보고서 생성이 실패한다.
3. 보고서의 모든 핵심 결론을 원자 주장과 출처로 역추적할 수 있다.
4. 실행 결과가 `artifacts/runs/<run-id>/` 아래에 독립적으로 보존된다.
5. 기존 테스트와 신규 evidence 기반 테스트가 모두 통과한다.

## 제품 결정

- 단일 진실 원천은 HTML이 아니라 `evidence.json`이다.
- HTML은 evidence의 파생 표현이며 직접 수정한 내용을 원본으로 취급하지 않는다.
- 분석 스킬은 orchestration 계층이고 검증·렌더링은 프로젝트 코드가 소유한다.
- `review.verdict=pass`와 `order_action=none`은 보고서 생성의 필수 조건이다.
- 배포와 외부 메시지 전송은 로컬 보고서 생성과 분리한다.
- 첫 웹 제품은 `127.0.0.1`에서 실행되는 단일 사용자·읽기 전용 애플리케이션이다.
- 웹 제품은 Codex 또는 향후 스케줄러가 만든 artifact만 조회하며 분석을 직접 실행하지 않는다.

## 미결정 사항

- 가격 데이터 공급자와 라이선스
- 국내 공시·미국 공시 수집기의 정식 인터페이스
- 투자 저널에 기록할 최소 필드
- 시나리오 평가 시점과 성과 측정 방식
- 자동 분석 스케줄러의 실행 주기와 실패 재시도 정책
